# 周一升旗检查模块设计

日期：2026-09-21
状态：已与用户确认

## 一、背景与目标

学校每周一举行升旗仪式，两个操场同时进行：

- 金轮操场：一年级、四年级
- 玉兔操场：二年级、三年级

值日生在仪式期间检查各班，发现下列任一情况各扣 1 分：

1. 未佩戴红领巾
2. 未穿着规范校服
3. 未穿黑鞋子
4. 升旗仪式迟到或逗留在班级

老师需要把当周扣分情况登记下来，**记录到具体学号**，让班主任知道是谁没有做到要求，并能把当天的结果导出为一张图片发到工作群。

本模块是已有「值日扣分记录」App 的第二个模块，与「日常值日检查」共用一个链接、一个手机桌面图标。

## 二、范围

包含：

- 周一升旗检查的录入、汇总、图片导出、历史查看、备份导入导出
- 学号登记（一个班一次可登记多个学号）

不包含：

- 不改动「日常值日检查」现有行为
- 不接入五年级及以上（学校情况不存在）
- 不做登录、服务器、多人协作、自动同步
- 不记录检查人

## 三、模块划分

App 顶部在现有「录入 / 汇总 / 历史与备份」标签之上，增加模块切换：

| 模块 | 标识 | 说明 |
| --- | --- | --- |
| 日常值日检查 | `daily` | 现有功能，逻辑不变 |
| 周一升旗检查 | `flag` | 本次新增 |

切换模块时，录入表单、扣分项、汇总视图、历史列表、导出图片全部按当前模块渲染。两个模块的数据存放在同一份本机数据里，用 `module` 字段区分，互不干扰。

App 名称由「值日扣分记录」改为「值日检查记录」，因为现在覆盖两类检查。

## 四、数据模型

记录对象在现有字段基础上增加两个字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `module` | `'daily'` \| `'flag'` | 缺省视为 `'daily'`，用于兼容旧数据 |
| `studentNos` | `string[]` | 学号列表，缺省 `[]`；只用于 `flag` 模块 |

`locationType` 扩展第三个取值 `'studentNo'`，只在 `flag` 模块出现。

学号规则：

- 每个学号是 1–3 位数字
- 一次最多登记 20 个
- 自动去重，并按数值升序排列
- 允许留空，表示整班问题（例如全班逗留在班级）

## 五、校验规则

`flag` 模块保存前校验：

1. 日期为 `YYYY-MM-DD`
2. 年级为 1–4
3. 班级号在范围内（一至三年级 1–18，四年级 1–23）
4. 扣分原因必须属于升旗检查的 5 项之一
5. 学号逐项校验为 1–3 位数字，最多 20 个；留空合法
6. 分值为大于 0 的整数
7. 选择「其他情况」时必须填写备注

`daily` 模块沿用现有校验规则。

## 六、分值规则

默认每个问题扣 1 分。填了学号时，分值默认等于学号个数（3 个学号 = 3 分），仍可手动改。

留空学号时默认 1 分。

## 七、操场归属

操场由年级自动决定，不需要手选：

| 年级 | 操场 |
| --- | --- |
| 一、四年级 | 金轮操场 |
| 二、三年级 | 玉兔操场 |

录入界面在选择年级后显示对应的操场标签，便于值日生确认没选错。

## 八、界面

### 8.1 录入页（flag 模块）

字段顺序：日期 → 年级 → 班级 → 操场标签（只读）→ 学号 → 扣分原因（5 项）→ 分值 → 备注 → 保存记录。

日期默认取最近一个周一（含当天，若当天是周一）。

学号输入框接受空格、逗号、顿号、分号分隔，例如 `3 7 12`、`3、7、12`、`3,7,12` 都解析为同一组。

录入页下方保留「今日记录」列表，每条显示 `班级 · 扣分项 · 学号 · 分值`，可删除。

### 8.2 汇总页（flag 模块）

按操场分两段，只显示**有扣分**的班级：

```
金轮操场（一、四年级）
  四年级23班（4分）
    未佩戴红领巾：3、7、12 号（3分）
    未穿黑鞋子：9 号（1分）
玉兔操场（二、三年级）
  二年级4班（1分）
    升旗迟到或逗留在班级：整班（1分）
当天合计：5分 · 2个班级 · 4条记录
```

同一班级内，相同扣分项的学号合并到一行并升序排列；没有学号的记录显示为「整班」。

### 8.3 导出图片（flag 模块）

导出一张 PNG，宽度 1080，内容自上而下：

1. 标题：`X月X日升旗检查扣分情况`
2. 段落标题：`金轮操场（一、四年级）`
3. 各班明细：班级（分数）→ 逐行扣分项 + 学号
4. 段落标题：`玉兔操场（二、三年级）`
5. 各班明细
6. 末行：`当天合计：X分 · Y个班级`

没有记录的操场不出现。文件名为 `YYYY-MM-DD-升旗检查扣分情况.png`。

当天没有任何记录时不导出，并提示「当天没有扣分记录，暂不能导出图片」。

### 8.4 历史与备份

历史列表只显示当前模块的日期。备份文件包含全部模块数据，`schemaVersion` 保持 1，合并/覆盖导入行为不变。

## 九、模块文件

| 文件 | 职责 |
| --- | --- |
| `js/modules.js` | 模块定义、升旗扣分项、操场归属 |
| `js/dates.js` | 最近一个周一、日期标题格式化 |
| `js/records.js` | 记录规范化与校验（按模块分支） |
| `js/summary.js` | 汇总（按模块分支） |
| `js/image-export.js` | 图片排版与绘制（按模块分支） |
| `app.js` | 界面状态与渲染 |

每个模块保持单一职责：解析/校验、汇总、排版互不依赖对方的内部结构。

## 十、错误处理

- 校验失败：在录入页提示具体原因，不保存
- 本机数据损坏：提示「本机数据格式不正确」
- 备份文件格式错误：提示「备份文件格式不正确」，不覆盖现有数据
- Canvas 导出失败：提示导出失败，数据不受影响

## 十一、测试

单元测试覆盖：

1. 操场归属：一年级→金轮、三年级→玉兔
2. 学号解析：多种分隔符、去重、排序、非法值、超过 20 个
3. 最近一个周一：周一当天、周二、周日
4. flag 记录校验：学号留空合法、非法学号报错、其他情况必须备注
5. flag 汇总：按操场分组、同学号合并、整班记录
6. flag 图片排版：标题、两段操场、只含有扣分的班级、末行合计
7. 旧数据兼容：缺少 `module` 字段的记录仍按 `daily` 读取
8. 现有 22 项测试全部保持通过

## 十二、部署

静态站点，部署到免费静态托管（GitHub Pages），手机与电脑用同一个链接访问，可「添加到主屏幕」当 App 使用，断网可录入。
